# HTTP-сервис FitGOIntegration (расширение 1С)

Собственный JSON API для FitGO — без SOAP `osmi_ws`.

## Метаданные

| Параметр | Значение |
|----------|----------|
| Расширение | `FitGOIntegration` (.cfe) |
| HTTP-сервис | `FitGOIntegration` |
| Корневой URL | `fitgo` |
| Шаблоны URL | `v1` |

Итоговый путь: `https://host:445/fitgo/hs/fitgo/v1/{метод}`

## Шаблоны URL в HTTP-сервисе

| Метод HTTP | Шаблон | Обработчик |
|------------|--------|------------|
| GET | `/v1/health` | `HealthGET` |
| GET | `/v1/client` | `ClientGET` |
| GET | `/v1/membership` | `MembershipGET` |
| POST | `/v1/membership/freeze` | `FreezePOST` |
| GET | `/v1/visits` | `VisitsGET` |
| GET | `/v1/card` | `CardGET` |

Префикс `/v1` входит в **Шаблон** каждого метода (проверено: `GET /fitgo/hs/fitgo/v1/health` → 200, `GET /fitgo/hs/fitgo/health` → 404).
Nest ходит по `FORMA_FITGO_URL=…/fitgo/hs/fitgo/v1`, поэтому шаблон без `/v1` из приложения недостижим.

**Имя** шаблона URL — одно слово (`freeze`); путь — в свойстве **Шаблон** (`/v1/membership/freeze`).  
**Обработчик** метода POST должен совпадать с именем функции в модуле: `FreezePOST`.

### Защита от опасных действий (500 на POST freeze)

Проведение документа «Операция с членством (заморозка)» в базовой конфигурации создаёт COM-объект
`WinHttp.WinHttpRequest.5.1` (рассылки/пуши по триггерному событию). Если у расширения включена
«Защита от опасных действий», в HTTP-сервисе (без UI) это превращается в исключение и ответ 500
с текстом «Предупреждение безопасности … Модуль "FitGO" выполняет подключение …».

Снять: Конфигуратор → Конфигурация → **Расширения конфигурации** → строка расширения →
снять флаг **«Защита от опасных действий»** (флаг «Безопасный режим» тоже должен быть снят).
Дополнительно можно снять тот же флаг у пользователя ИБ, под которым идёт Basic Auth
(Администрирование → Пользователи → пользователь → «Защита от опасных действий»).

Полный модуль HTTP-сервиса: [`scripts/windows/FitGOIntegration_HTTP.bsl`](../FitGOIntegration_HTTP.bsl) — вставить целиком в модуль сервиса.

## Порядок внедрения

1. **Только `/health`** → опубликовать → `.\probe-fitgo-api.ps1` → HTTP 200
2. **`/client?phone=`** — поиск клиента по телефону
3. `/membership`, `/visits`, `/card`

## Авторизация (в каждом обработчике)

Проверять заголовки как в API v3:

- `apikey`
- `Authorization: Basic ...`

При неверных данных → HTTP 401, JSON `{ "error": { "code": 401, "message": "Unauthorized" } }`

## Формат ответа

Успех:

```json
{ "data": { ... } }
```

Ошибка:

```json
{ "error": { "code": 404, "message": "Client not found" } }
```

## BSL — модуль HTTP-сервиса (шаблон)

> Имена справочников/регистров **уточнить в конфигураторе** по тестовому телефону `+375296600435`.

```bsl
Функция HealthGET(Запрос)
    Ответ = Новый HTTPСервисОтвет(200);
    Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
    Ответ.УстановитьТелоИзСтроки("{""data"":{""status"":""ok""}}");
    Возврат Ответ;
КонецФункции

Функция ClientGET(Запрос)
    Если НЕ ПроверитьАвторизациюFitGO(Запрос) Тогда
        Возврат ОтветОшибки(401, "Unauthorized");
    КонецЕсли;

    Телефон = НормализоватьТелефон(Запрос.ПараметрыЗапроса.Получить("phone"));
    Если ПустаяСтрока(Телефон) Тогда
        Возврат ОтветОшибки(400, "phone required");
    КонецЕсли;

    Клиент = НайтиКлиентаПоТелефону(Телефон); // TODO: ваш запрос к справочнику
    Если Клиент = Неопределено Тогда
        Возврат ОтветОшибки(404, "Client not found");
    КонецЕсли;

    Данные = Новый Структура;
    Данные.Вставить("externalId", Строка(Клиент.УникальныйИдентификатор()));
    Данные.Вставить("firstName", Клиент.Имя);
    Данные.Вставить("lastName", Клиент.Фамилия);
    Данные.Вставить("phone", Телефон);

    Возврат ОтветJSON(200, Данные);
КонецФункции

// Аналогично: MembershipGET, VisitsGET, CardGET
```

## Как найти объекты в конфигурации

1. Пользовательский режим → найти клиента `+375296600435`
2. Конфигуратор → «Все функции» → поиск по номеру телефона в данных
3. Типовые кандидаты в «Фитнес клуб»:
   - Справочник клиентов / контрагенты
   - Регистры сведений/накопления: абонементы, посещения
   - Карты доступа

Спросите у админа 1С: **«Из какого объекта читается ЛК клиента по телефону?»**
