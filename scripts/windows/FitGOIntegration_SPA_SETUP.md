# Настройка SPA ↔ 1С (FitGOIntegration) на сервере клуба

Сделано с Mac (уже готово в репозитории):

- Nest API снова на `FITNESS_PROVIDER=forma` (не mock)
- `GET /v1/health` и `GET /v1/membership` отвечают 200
- BSL-обработчики `ConsumeServicePOST` / `SpaSalePOST` + бизнес-функции в:
  - `FitGOIntegration_HTTP.bsl`
  - `FitGOIntegration_Клиенты.bsl`
- Имена квот в seed/admin совпадают с живым абонементом VIP:
  - `Массаж классический общий` (остаток 1)
  - `Анализ состава тела` (остаток 1)

Новые URL с Mac сейчас дают **404** — шаблоны HTTP ещё не опубликованы в 1С. Ниже — что сделать в конфигураторе.

Тест-клиент: `externalId=ff94bf6a-b4d2-11e8-80e9-7085c20c362e`, телефон `375296600435`.

---

## 0. Перед правками

1. Откройте конфигуратор расширением **FitGOIntegration** (не основную конфигурацию).
2. У расширения снимите **«Защита от опасных действий»** (иначе проведение документов → HTTP 500 про WinHttp).
3. Убедитесь, что публикация HTTP `fitgo` на `:8445` уже работает (health/membership).

---

## 1. Обновить модули из репозитория

Скопируйте содержимое файлов с Mac/git в соответствующие объекты расширения:

| Файл в репо | Куда в 1С |
|-------------|-----------|
| `scripts/windows/FitGOIntegration_HTTP.bsl` | Модуль HTTP-сервиса `FitGOIntegration` (целиком) |
| `scripts/windows/FitGOIntegration_Клиенты.bsl` | Общий модуль `FitGOIntegrationКлиенты` (целиком) |

Если правите точечно — минимум добавить:

- в HTTP: функции `ConsumeServicePOST`, `SpaSalePOST`
- в Клиенты: `СписатьУслугуЧленства`, `ПродатьСпаУслугу` и хелперы рядом с `УстановитьОперациюЗаморозка`

## 2. Два новых шаблона URL (критично — с `/v1`)

В HTTP-сервисе FitGOIntegration → **Шаблоны URL** → добавить:

### Шаблон A — списание квоты

| Поле | Значение |
|------|----------|
| Имя | `consume-service` (любое короткое) |
| **Шаблон** | `/v1/membership/consume-service` |
| Метод | **POST** |
| Обработчик | `ConsumeServicePOST` |

### Шаблон B — платная SPA

| Поле | Значение |
|------|----------|
| Имя | `spa-service-sale` |
| **Шаблон** | `/v1/spa/service-sale` |
| Метод | **POST** |
| Обработчик | `SpaSalePOST` |

Ориентир: шаблон freeze уже должен быть `/v1/membership/freeze` → `FreezePOST`.

**Частая ошибка:** шаблон без `/v1` (`/membership/consume-service`). Nest ходит на  
`https://192.168.1.20:8445/fitgo/hs/fitgo/v1/...` → такой шаблон даст 404 из приложения.

## 3. Обновить конфигурацию БД и опубликовать

1. **F7** — обновить конфигурацию БД (принять изменения расширения).
2. Переопубликовать HTTP-сервис **`fitgo`** (Администрирование → Публикация на веб-сервере / IIS/Apache, как обычно для FitGO).
3. При необходимости перезапустить Apache на `:8445` (только если после F7+публикации всё ещё 404).

## 4. Проверка с Mac (не с RDP)

```bash
set -a; source apps/api/.env; set +a
BASE="$FORMA_FITGO_URL"   # .../fitgo/hs/fitgo/v1
EXT=ff94bf6a-b4d2-11e8-80e9-7085c20c362e

# контроль
curl -sk -H "apikey: $FORMA_API_KEY" -H "Authorization: Basic $FORMA_BASIC_AUTH" "$BASE/health"

# списание 1 массажа (write!)
curl -sk -X POST \
  -H "apikey: $FORMA_API_KEY" -H "Authorization: Basic $FORMA_BASIC_AUTH" \
  -H "Content-Type: application/json" \
  -d "{\"externalId\":\"$EXT\",\"serviceName\":\"Массаж классический общий\",\"bookingRef\":\"probe-consume-1\",\"occurredAt\":\"2026-09-17T12:00:00.000Z\",\"durationMin\":50}" \
  "$BASE/membership/consume-service"

# платная продажа (write!)
curl -sk -X POST \
  -H "apikey: $FORMA_API_KEY" -H "Authorization: Basic $FORMA_BASIC_AUTH" \
  -H "Content-Type: application/json" \
  -d "{\"externalId\":\"$EXT\",\"serviceName\":\"Классический спа-массаж 50 мин\",\"bookingRef\":\"probe-sale-1\",\"occurredAt\":\"2026-09-17T12:05:00.000Z\",\"priceMinor\":7500,\"currency\":\"BYN\",\"durationMin\":50}" \
  "$BASE/spa/service-sale"
```

На Windows можно: `scripts/windows/probe-fitgo-spa.ps1`.

### Ожидаемые коды

| HTTP | Значение |
|------|----------|
| **200** + membership JSON | Успех; у consume `Массаж классический общий.remaining` стал 0 |
| **404** пустой/короткий | Шаблон не опубликован или без `/v1` / обработчик не привязан |
| **401** | apikey / Basic |
| **409** | Нет остатка квоты (нормально после первого успешного consume) |
| **400** с текстом 1С | Документ не провелся — смотреть текст (вид операции, реквизиты) |
| **500** «Предупреждение безопасности» / WinHttp | Вернуть шаг 0: снять защиту от опасных действий |

## 5. Что делает бизнес-логика (если 400 при проведении)

### Ошибка формы членства «Недопустимое значение параметров» / Декорация Class_

При открытии истории занятий в `ЧленствоПакетУслуг` форма делает `Элементы.Вставить("Class_" + ИдСтроки)`.  
Если у `Документ.Занятие` пустой `ИдентификаторЗанятия` (или id с дефисами) — падает UI.

**Уже созданные FitGO-пробы:** откройте список Занятий с комментарием `FitGO SPA`, проставьте `ИдентификаторЗанятия` (32 hex без `-`) или пометьте на удаление лишние пробы — форма абонемента снова откроется.

**Новые списания:** BSL выставляет `ИдентификаторЗанятия` без дефисов + счётчики посетивших.

### Ошибка формы салона «Индекс находится за границами массива» / `СоставЗанятия[0]`

Форма `ФормаПосещенияСалонаКрасоты` при открытии читает `Занятие.СоставЗанятия[0].ОснованиеОплаты`.  
Если ТЧ пустая (типичные FitGO-пробы до harden) — **нельзя открывать** документ двойным кликом.

**Сразу (без открытия формы):**

1. В списке «Занятия» клиента выделите строки с комментарием `FitGO SPA` → ПКМ → **Пометить на удаление** (не «Открыть»).
2. Или в режиме предприятия выполните в консоли (после вставки актуального `FitGOIntegration_Клиенты.bsl` + F7):

```
Р = FitGOIntegrationКлиенты.ОчиститьБитыеFitGOSpaЗанятия();
Сообщить("marked=" + Р.marked + " skipped=" + Р.skipped + " err=" + Р.error);
```

3. Либо HTTP (если опубликован шаблон):  
   `POST /v1/spa/cleanup-broken-visits`  
   тело `{"externalId":"ff94bf6a-b4d2-11e8-80e9-7085c20c362e"}`.

После пометки обновите список — форма клиента/занятий снова открывается.

**Новые списания:** BSL не пишет документ без `СоставЗанятия[0].ОснованиеОплаты` и откатывает проведение, если ТЧ опустела после записи.

## 6. После успешного curl — FitGO

1. API уже на `forma` — данные абонемента снова в клиентском дашборде.
2. В `/admin/spa` правило квоты: **имя = как в 1С** (`Массаж классический общий`).
3. Запись SPA с `QUOTA` вызовет consume; с `PAID` — sale.
4. Если consume/sale ещё 404 — бронь в приложении откатится (так задумано).

Пересоздать правила из seed (опционально):

```bash
cd apps/api && pnpm exec prisma db seed
```
